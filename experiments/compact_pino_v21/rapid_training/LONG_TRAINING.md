# Compact PINO V2.2：长训练配置与预算评估

更新日期：2026-11-26。本文对应本目录的 `prepare.py`、`run.py`、`runtime.py`，以及 `training/runner.py` 当前实现。

**首选路线是复用已验证 checkpoint 的几何编码，只训练局部响应；先完成两臂各 104 步的定向短试，再让通过完整筛选的胜出臂续训。** 长训预设上限为绝对 10,000 次更新、10,000 次尝试、48 小时累计 runner 时间，达到任一边界即停止。这些数字是预算上限，不是必须用满的训练量，也不是 48 小时内达到物理要求的保证。

目前合成 CPU 测试已验证实际 Token16 的两种响应、真实参数更新、物理损失梯度、冻结状态与逐值断点恢复。**这不构成 Work GPU 验证或正式长训 GO。** 当前若仍缺原协议要求的合格 Full J 或其他保护项分母，必须保留证据不足；不能把有界研究短试的资格当成完整长训资格。

## 1. 推荐配置

| 项目 | 首选配置 | 采用理由与实施边界 |
|---|---|---|
| 运行设备 | Work 的单张 RTX 5090 D，`cuda:0` | 使用已有目标设备；CUDA、显存和训练耗时必须现场验证，不能由显卡型号推算合格时间。 |
| 材料表示 | 原 256³ 守恒材料与固定材料十矩 | 不在同一实验内同时更改材料语义、体素分辨率和响应结构。 |
| 几何编码 | 共享 P-CRAFT/U-FNO，32³ 与 64³ 上下文，Token16 | 复用当前实现和相同冻结权重；不增加独立 Jacobian 预测头。 |
| 局部响应 | 两臂筛选所得的 `bounded_cubic` 或 `monotone_warp` | 新响应不是默认胜出者；依据配对结果选择。 |
| 可训练范围 | `training_scope="response"` | 实测当前 Token16 总参数 2,976,772，仅训练完整响应 MLP 的 12,674 个参数。 |
| 初始化 | 首次短试 `response_zero_init=true` | 两臂最后输出层置零，Epoch 0 恢复同一无学习三次响应；隐藏层和冻结编码器使用同一权重源。 |
| 优化器 | Adam，学习率 `3e-5`，`betas=(0.9,0.999)`，`eps=1e-8`，`weight_decay=0` | 与 runner 实现一致；本轮不增加优化器搜索。 |
| 学习率调度 | 常数；代码为 `StepLR(step_size=1,gamma=1)` | scheduler 状态仍进入 checkpoint 和精确恢复。 |
| batch / 累计 | `batch_size=1`，无梯度累计 | 简化曝光与更新计数，保持当前已验证训练路径。 |
| 精度 | `amp="off"`；Moment 与物理积分保留 float64 | 不是把整网改成 float64；网络参数维持实现本身的 dtype。当前复杂 Fourier 参数的 fp16 AMP 没有资格，runner 会拒绝该组合。 |
| 积分块大小 | `chunk_size=65536` | 首轮沿用；先测峰值内存和实际活动点数，再决定是否需要独立调整。 |
| 积分规则 | 首选候选 `gl2`，训练侧校准后冻结 | `prepare.py` 默认 gl2，通用 `TrainConfig` 默认仍是 tetra4。必须明确写入配置，不能依赖不同入口的隐式默认值。 |
| 外带宽 | `H=voxel_pitch` | 本轮固定；不同时搜索带宽与响应头。 |
| 损失 | Moment + 合格 J + 同点驻点向量匹配 + 约束匹配 | 各项使用自己的资格掩码与有效分母；普通迭代位置的原生参考向量可以非零。 |
| 损失权重 | `lambda_J=1`；R、C 用本轮校准值；辅助损失 0 | 不能照搬旧全模型系数，也不能把烟测的 `0.1` 当成正式校准值。 |
| 随机性 | seed `830251`，`deterministic=true` | 两臂共享初始权重、曝光顺序与数值设置；精确恢复只承诺同一已声明运行环境内。 |

参数数量来自实际完整模型的 `rapid_training/smoke.py` 运行；不是根据结构名称估算。GPU 上应重新运行同一烟测并记录实际设备、源文件哈希、配置以及恢复结果。

### 缓存预算

`prepare.py` 生成的快速训练配置使用以下值。它们与直接创建通用 `TrainConfig()` 的默认值不同。

| 缓存 | 快速配置 | 通用默认 | 保存内容和寿命 |
|---|---:|---:|---|
| `static_cache_bytes` | 128 MiB | 128 MiB | 与参数无关的 CPU 几何输入。 |
| `query_cache_bytes` | 256 MiB | 128 MiB | 有限切割面和材料的静态查询准备；不保存学习图或可变原生运动。 |
| `frozen_feature_cache_bytes` | 256 MiB | 64 MiB | 冻结编码器产生的未投影特征表；可跨响应参数更新复用。 |
| `evaluation_cache_bytes` | 64 MiB | 64 MiB | 一次评估会话内的 inference-only 几何特征对象。 |

前三项是算子缓存，第四项是 runner 的评估缓存。预算是各缓存保留对象的上限，**不是整个程序的内存或显存上限**；材料文件、网络、暂存激活、积分点及反向图仍有额外占用，缓存之间也可能引用同一张量。

冻结模块的参数、缓冲区与 eval 状态均受检查。材料、固定材料、密度、冻结权重或缓冲、dtype/device 等身份改变时，缓存失效。响应第一层投影每个计算图重新生成，不跨更新保存。Work 应同时报告 `encoder_calls`、命中/淘汰次数、缓存字节数与 CUDA 实测峰值；单次合成查询的缓存速度不能外推为真实训练或原生求解加速。

## 2. 优先严格迁移现有 checkpoint

正式长训优先继承已经验证过的几何特征。`geometry_and_hidden` 迁移会读取同一个 canonical checkpoint 的编码器、静态 attention 和响应隐藏层，再把响应最后一层归零。两个短试臂使用相同 checkpoint SHA256，只有响应函数含义不同。

当前迁移入口只接受本 runner 的 `compact_pino.training-state.v1` 格式，并检查科学配置摘要、完整 state_dict 键集合、张量形状、dtype 和有限值。任意外部 `.pt`、只含部分权重的文件或未经转换验证的历史 checkpoint，不能靠 `strict=False` 绕过这些检查。确需转换时，应单独完成格式转换、逐键核验、同点输出比对与迁移回执，再进入本轮校准。

初始权重迁移和精确续训是两件事：

- **首次构建两个短试臂：**使用 `geometry_and_hidden`，建立新的 optimizer、RNG、采样器和 run；旧响应最后层和旧 optimizer moments 不迁入。
- **胜出臂进入长训：**从筛选报告绑定的确切 checkpoint 用 `--resume` 继续，恢复 optimizer、scheduler、scaler、RNG、曝光 cursor 和计数。不要再次归零输出层；不要把某臂第 104 步的最终状态替代真正入选的第 52 或 78 步状态。

若没有可验证的已有 checkpoint，工具可以从确定随机初始化开始研究短试，但必须如实登记这一点；冻结随机特征不等同于复用经过学习的几何表示。不能据此提前承诺长训效果。

## 3. 曝光日程：全合格训练池参与，首段定向修复

在任何候选结果揭晓前，从完整合格 train pool 生成并冻结 **10,000 条有序曝光**及其 SHA256，而不是只循环 24 个新点。这里的 10,000 是条次，不是独立查询数，也不是 epoch 数。开发来源、面条诊断和盲测来源不进入训练池。

前 52 条包含首批 24 个不同合法物理查询的两遍曝光，前 26 条覆盖这些不同查询。正式选模还必须检查该 checkpoint 的实际回执：每个新增查询都已完成至少两次有效驻点与约束参与、成功反传和已提交更新。仅出现在日程里不算完成。

第 53 条起，当前实现按以下八位置模板安排：`physics、high、jacobian、general、physics、high、low、general`。每个桶内部先轮换来源，再在来源内按无放回次序取样；桶为空时显式回退到 general 并登记次数。前 104 条另确保高保留曝光至少 26 条。

因此，后续长训仍保留定向样本，并持续从完整训练池引入普通查询、低/近零保留和合格导数查询。**这是桶内来源平衡，不保证所有训练来源或独立查询最终完全等量曝光。** 应审核日程报告及实际曝光回执，列出来源、曲面、保留比例、轨迹阶段、独立查询数、重复次数和有效导数数量。

固定日程不能凭空补齐 R8 或 Full J 资格。不合格导数行可以保留其合格 Moment 或物理目标，但不得伪造 Jacobian 分母。训练数据后续更新会改变 manifest 身份；不能在一个精确续训链上悄悄换数据或扩展日程。

## 4. 物理损失重新校准

使用 `calibrate.py`，在合格训练侧 cohort 中按来源选择查询，读取与实际训练一致的初始 checkpoint、冻结范围、积分规则和响应初始化。该过程不创建优化器、不进行参数更新。

保留 `lambda_J=1`。对两种响应的同点 M、J、R、C 梯度做联合统计，以 R 与 C 各自约占 M+J 梯度范数 10% 为起始目标；实际实现取两臂、各查询有效正比例的合并中位数，生成两臂共享的 R、C 系数。某项没有合格分母或有效梯度时，记录缺失，不能从无效值“校准”出一个系数。

10% 是起始工程目标，不保证每个样本或每个后续步骤都维持此比例。0/26/52/78/104 的梯度探针应同时报告各项范数、夹角、有效分母与资格原因，用于识别物理损失压倒 Moment/J 或没有实际参与的问题。模型更换、解冻范围更换、初始权重更换或积分规则更换后，旧校准回执不再适用。

## 5. 训练窗口、固定评估和停止条件

| 阶段 | 可执行预算 | 评估与决策 |
|---|---|---|
| G0 软件与数据正确性 | Work GPU 两臂真实更新、断点恢复，结合教师/材料/隔离等凭据 | GPU 烟测不等于科学晋级；数据和任务身份必须正确。 |
| 配对短试 | 每臂绝对最多 104 updates / 104 attempts，最多 6 小时累计 runner 时间 | 初始 0；26/52/78/104 固定评估。0 与 26 仅监控，候选为达到实际物理曝光要求的 52/78/104。 |
| G1 完整筛选 | 按原协议评估选中 checkpoint | Moment 至少改善 5%；原有保护项最多退化 5%；无学习基线、来源差异、末段残差和缺失项另列。 |
| 获准的长训 | 胜出臂从确切入选 checkpoint，绝对最多 10,000 updates / 10,000 attempts / 48 小时 | 继续既有日程及协议；新增评估在 500、1,000、1,500……10,000。 |

`prepare.py` 在短试前就冻结完整节点集合 `26/52/78/104` 加每 500 步及最终目标步；0 由初始化评估处理。`run.py` 通过 `evaluate_every=0` 遵循这些显式节点，不另设一个互相冲突的评估频率。checkpoint 另按当前入口每 26 次尝试及评估时保存。

“绝对 10,000”包含恢复点已有的更新与尝试。例如从第 78 次已提交更新恢复，并不是再增加 10,000 次。饱和区域没有参数依赖等跳过情况会消耗尝试和曝光，却不增加更新数；因此可能在少于 10,000 次有效更新时耗尽预算。不得偷偷循环固定日程或追加尝试补满。

48 小时是累计 runner 会话预算，按 checkpoint 续接，在更新边界检查；可能超过边界一个正在执行的更新或评估。初次数据装载、外部标注/校准、独立原生验收及被放弃分支的额外运行成本仍需另行计账。两个短试臂、候选筛选和原生求解实验也不能隐藏在胜出臂的训练时间之外。

非有限损失/梯度、错误任务绑定、恢复不一致等属于正确性失败，应停下定位。预登记的趋势停止规则是：完成定向段后，连续两个检查点的主项差于 E0 且 high 超过 1.05，停该臂，最早可在 52 与 78 两次检查后触发。**104 步未通过不自动追加到 208、312 或长训。**

当前 Full J 等仍缺合格证据时，原完整 gate 不具备 GO。可继续已有授权内的定向研究和补数，但不能把缺失项改成通过，也不能直接生成 `mode=long` 的授权回执。完整筛选通过后，`long` 还要求数据、配置、协议和候选 checkpoint 与筛选报告逐项匹配。

## 6. 怎样估算能否在本周完成

先完成实际 GPU 短试，至少取得多次正常已提交更新、完整开发评估耗时、活动积分点分布和显存峰值，再调用现有工具：

```bash
python -m experiments.compact_pino_v21.rapid_training.runtime \
  --run /absolute/path/to/completed_trial \
  --protocol /absolute/path/to/prepared/protocol.json \
  --total-steps 10000 \
  --warmup 3 \
  --output /absolute/path/to/new_runtime_projection.json
```

工具舍弃前 3 次已提交更新，报告更新耗时 P50/P95/P99、已跳过尝试、CUDA 峰值和实测完整评估中位耗时；按剩余冻结评估节点计算评估成本。默认投影形式是：

\[
T_{\mathrm{remaining}}\approx
N_{\mathrm{remaining\ updates}}\,t_{\mathrm{update,P95}}
+N_{\mathrm{remaining\ eval}}\,t_{\mathrm{eval,median}}.
\]

还应另计未包含在上述样本中的数据装载、首次各几何编码、校准/探针、checkpoint I/O、失败尝试和最终原生验收成本；已经包含在逐步计时中的编码不重复相加。更复杂几何与新活动点规模可能使后续查询比短试更慢。工具输出是描述性投影，不是时间置信上界；若没有完整评估记录，评估成本会明确缺失。

**可承诺的是先设置有限窗口并交付可恢复权重及真实评估，不能在没有 Work 测量前承诺某张卡几小时训完或一周内一定满足物理验收。** 如果 P95 投影明显超过剩余预算，应在开长训前调整预算和实验协议。若增加缓存、改变 chunk、精度或可训练范围，也应重新验证运行身份和可恢复性，不能在精确续训过程中手改科学配置。

## 7. 为什么暂不默认解冻整个编码器

当前最明确的研发目标是切割局部响应及末段物理预测；先冻结几何侧，可以把新数据、响应函数和物理损失的效果直接测出来。它同时使同一几何的静态编码跨更新可复用，减少反向图和优化器状态，但不能据参数数量推算整体训练加速倍数：查询准备、积分和物理导数仍有成本。

如果在多个训练来源上出现可复现的响应拟合上限，而材料、标签、积分和任务接口已核对，再开展**独立的解冻短试**。必须重新界定可训练层、建立新 optimizer、重新校准物理损失、冻结新协议，并重新执行实际更新及恢复检查。`training_scope="all"` 下编码器每步变化，不能继续跨更新复用冻结特征表。它不是当前 response-only checkpoint 的无缝配置切换，也不是立即启动全模型长训的理由。

## 8. 训练后的最终证据

长训结束只表示获得了某个预算下的权重。是否能替代或加速原生优化，还需在相同任务、初值、约束、线搜索、停止条件及独立原网格验收下比较。沿用项目现有原生驻点 `1e-12`、平衡约束 `1e-6` 标准，不以放宽验收换取“成功”。其他任务 profile 应严格使用其冻结的原生标准。

并行实测三种路线：纯原生、神经算子直接候选、神经候选加原生校正。热启动若能更快取得合格解，可以成为实用路线；混合路线通过不改写直接候选失败。应从读入原网格开始计算冷启动，并单列复用缓存的热启动，把编码、逐查询构面、传输、失败、回退、校正和最终验收全部计入。

最终交付至少包含：选中权重与恢复回执、源文件/数据/标签/日程哈希、实际曝光与损失参与记录、完整开发逐查询结果、无学习与历史锚点对照、分来源/保留率/导数/轨迹阶段结果、全部原生求解记录和原始计时。独立几何、配对初值、合格率、目标值与耗时统计继续按冻结协议报告；不以平均 Moment 改善代替物理成功证据。

## 实现依据

- `training/runner.py`：配置默认值、Adam、常数调度、精确迁移/恢复、物理曝光与墙钟检查。
- `rapid_training/prepare.py`：快速配置缓存值、首段与完整曝光日程、固定评估节点、预算与停止协议。
- `rapid_training/calibrate.py`：两臂共享的训练侧梯度校准。
- `rapid_training/runtime.py`：实测更新和评估时间投影。
- `training/admission.py` 与 `rapid_training/authorize.py`：短试和完整长训的独立准入检查。
- `rapid_training/smoke.py`：实际 Token16 双臂更新、冻结缓存、物理梯度和逐值断点恢复。
