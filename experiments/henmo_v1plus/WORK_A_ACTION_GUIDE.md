# Work A：HENMO V1+ 材料、教师与数据交付

**职责：Work A 负责数据与物理凭据；Work B 负责框架运行、训练、效率及原生求解。** 本轮不要求先把全部数据升为 1024 再开始实验。先保留可复现的 256 快照作共同对照，按薄壁/空腔等表示风险补充 512，少量困难几何再做 1024 敏感性验证。

## A1. 材料交付

每件几何一次预处理，交付连续原网格及登记后的材料资产。代码接受 `PreparedMaterial`：完整内部 RLE 区间采用解析十矩，边界部分体素采用已有原网格构建流程生成的正权积分点。不能只把二值 RLE 插值放大并登记为高分辨率物理真值。

- [ ] 身份字段包含原网格 SHA256、坐标变换、单位、密度、原点、pitch、native side、材料构建版本和参数。
- [ ] `native_material_resolution` 在查询元数据、材料资产和教师凭据中一致。改变 256→512 产生新材料身份。
- [ ] 完整体素与部分体素互斥，RLE 区间无重叠，部分积分点位于所属体素内、权重严格为正。
- [ ] 固定材料独立给出十矩，仅加一次；包含非零固定壳的验收例。
- [ ] 原网格独立完整十矩与材料总十矩逐分量比较，以 `m*L^k` 缩放，最差分量误差 ≤ `1e-8`。失败的材料不得因质量一项接近而准入。
- [ ] 薄壁、空腔、断连体和中心落在材料外的部分体素均保留；连通性最终仍由原网格几何检查。
- [ ] 同一材料跨查询复用同一身份与内容。新 loader 的 prepared 路径按经校验资产身份共享，避免每条查询重复展开高分材料。

这里的完整十矩检验不证明所有部分切割都准确，部分切割仍须独立教师标签。512/1024 支持通过稀疏材料聚合实现，不需要构建稠密 512³/1024³ 网络张量。

## A2. 每条查询的教师与导数

- [ ] 直接使用冻结部署版本构造的有限、有向、带端盖操作数；存顶点、面片、端盖身份、保留侧和参数身份。
- [ ] 十矩顺序固定为 `[m,x,y,z,xx,yy,zz,yz,xz,xy]`。
- [ ] 教师使用同一原网格与同一操作数。真实布尔结果/切后十矩只进监督、校正、验收，不放进模型查询输入。
- [ ] 若导数有效，提供原始十系数或固定秩 chart 下的顶点运动、参数尺度、合格事件邻域和外部验证凭据。
- [ ] Full-J、R3、R8 各自按其有效参数空间扰动。变秩、接触、拓扑事件、最近面歧义不能伪造为零导数。
- [ ] 同面换侧验证互补；不得重新施加“两次反号重建切面必互补”的错误前提。
- [ ] 不合格 J 的行可成为合格 Moment-only 样本，但必须明确 mask；不可填零进 Jacobian 损失。

## A3. 补标优先级

| 优先级 | 补什么 | 目的 |
|---|---|---|
| 1 | 训练来源的成功轨迹末段、终点和局部有效邻域，特别是中/高保留 | 检查和降低“平衡满足但最优性错误”的十矩偏差 |
| 2 | 跨来源抛物曲面的合格 R8、首批具有完整资格的 Full-J | 补导数监督空白；不把仅两条开发 R8 当作稳定结论 |
| 3 | 低保留/近零、薄壁/空腔与拒绝事件对照 | 检查低质量区域相对误差及原生接管条件 |
| 4 | 同一原网格的 256/512/1024 材料表示对照 | 分离材料表示误差、响应近似误差和学习收益 |

至少逐行提供来源、几何、曲面类型、保留比例、轨迹阶段、是否终点、是否原生验收通过、导数资格与拒绝原因。阶段标签包括 initial、iterate、near_convergence、endpoint、event/rejection，实际字段约定以当前 metadata schema 为准，不用自由文本替代已有身份。

覆盖检查精确识别 `near_convergence` 与 `endpoint`，不要用别名替代这两个阶段。若将来启用残差辅助损失，沿用已有 `cpino_fixed_residual_target_v1` 凭据，并保留该查询的原生参考矩、真实残差和固定乘子；普通迭代点不能因为进入训练就把目标残差改成零。默认 Pilot 的辅助损失权重仍为 0。

**不需要盲目扩张随机查询量。** 先覆盖缺失的来源/曲面/阶段组合；如果候选与确定性基线都在同一切割失准，继续重复同类随机点不能解释原因。粗节点的局部标签目前不是训练入口的必需字段：现有最终十矩和合格 J 可以直接训练；是否增加局部教师取决于短训归因结果。

## A4. 交付后的自查

```bash
python -m experiments.henmo_v1plus.cli audit-data \
  --manifest /absolute/new/henmo_export/training_manifest.json \
  --config experiments/henmo_v1plus/configs/pilot512.json \
  --mode trial --output /absolute/new/henmo_data_audit.json
```

该 config 限定一个实际 native side。虽然 exporter 可以显式接受多个 side，当前 HENMO CLI 的单次审计/训练仍要求所加载材料与该配置相同；混合分辨率交付需要分别导出/审核为对应的独立快照。不要用 512 配置读取 256 材料，也不要仅修改 JSON side 欺骗分辨率检查。

需要交给 Work B 的文件：

1. 原网格、固定材料、任务初值/配置和身份清单。
2. 可搬移的材料、有限操作数、十矩、导数资产及哈希。
3. 正式 `training_manifest.json`、source authority、逐行 qualification 及拒绝行。
4. `henmo_data_audit.json` 和来源 × 曲面 × 保留比例 × 轨迹阶段覆盖表。
5. 完整材料十矩对照、终点复算、有效事件邻域证据。
6. 原开发 222 条与新开发诊断的明确映射，封存独立评估来源的身份。

**完成标准**：资产能被真实模式读取、身份/来源隔离一致、完整材料十矩通过、有效性 mask 可追溯。缺失 R8、Full-J 或某保留档应写“证据不足”，不能用更多 Moment 行替代这些分母。
